02 / How publishing works

Nothing goes public by accident.

Work happens in a private repository. Publication is a deliberate, manual step, and only the approved parts of a project ever leave it.

01
In the private repo
Projects live and develop in the klub's own repository, where drafts, dead ends and half-finished code are allowed to be exactly that.
02
Marked for publication
A project is published only once it is explicitly marked for it and a maintainer runs the publishing step by hand. There is no automatic path out.
03
Copied to the public repo
The approved folder and its write-up are copied to a public mirror, which this page indexes. The private repository is never exposed.
03 / What counts

Findings, tools, and dead ends.

A project can be a piece of strategy research, a simulation, a small library other members can use, an educational write-up, or an investigation that ended in nothing. All of them belong here.

Publishing the ones that failed is not modesty. A question you can rule out is a real result, and a library that only contains successes is not describing the work honestly.
